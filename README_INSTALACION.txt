SIGAT CMV - NOTIFICACIONES DE TICKETS + BACKUPS\n=================================================\n\nARCHIVOS A AGREGAR / REEMPLAZAR\n--------------------------------\nAGREGAR:\n- src/pages/Backups.jsx\n- supabase/functions/notificar-ticket/index.ts\n- supabase/functions/backups-sigat/index.ts\n\nREEMPLAZAR:\n- src/App.jsx\n- src/components/layout/Sidebar.jsx\n- src/pages/SolicitudPublica.jsx\n\nSQL:\n- database/NOTIFICACIONES_BACKUPS.sql\n\nPASO 1 - SUPABASE SQL\n---------------------\nEjecuta completo database/NOTIFICACIONES_BACKUPS.sql en SQL Editor.\n\nPASO 2 - RESEND / CORREO\n------------------------\nLa notificación usa Resend desde una Edge Function.\nConfigura estos secretos en Supabase Edge Functions:\n\nRESEND_API_KEY=...\nRESEND_FROM_EMAIL=SIGAT CMV <notificaciones@TU-DOMINIO-VERIFICADO>\n\nEl correo DESTINO se configura después dentro de SIGAT:\nAdministración > Copias de seguridad > Correo para nuevos tickets.\n\nOpcionalmente también puedes definir:\nTICKET_NOTIFICATION_EMAIL=correo@dominio.com\nSi existe este secreto, tiene prioridad sobre el correo guardado en SIGAT.\n\nPASO 3 - DESPLEGAR EDGE FUNCTIONS\n----------------------------------\nDesde la raíz del proyecto:\n\nsupabase functions deploy notificar-ticket --no-verify-jwt\nsupabase functions deploy backups-sigat\n\nIMPORTANTE:\n- notificar-ticket es pública porque /solicitud no requiere login.\n  La función NO permite elegir destinatario y solo envía una vez por ticket.\n- backups-sigat exige sesión ADMIN dentro de la propia función.\n\nPASO 4 - REACT\n--------------\nReemplaza/agrega los archivos indicados arriba y ejecuta:\n\nnpm run build\n\nLuego publica:\n\ngit add .\ngit commit -m "Agrega notificaciones de tickets y backups"\ngit push\n\nVERCEL hará el redeploy.\n\nFUNCIONAMIENTO DE NOTIFICACIONES\n--------------------------------\n- Cuando un funcionario crea un ticket desde /solicitud:\n  1. El ticket se guarda.\n  2. Se crea una cola de notificación.\n  3. La página llama a notificar-ticket.\n  4. Se envía el correo configurado.\n  5. La notificación queda marcada ENVIADA.\n- Los mantenimientos internos creados por ADMIN/TECNICO no envían correo.\n- En el Sidebar, Solicitudes / Tickets muestra un contador rojo de\n  PENDIENTE + ASIGNADA + EN_PROCESO y se actualiza cada 30 segundos.\n\nFUNCIONAMIENTO DE BACKUPS\n-------------------------\nAdministración > Copias de seguridad permite:\n- Crear copia manual.\n- Ver historial.\n- Descargar JSON de respaldo.\n- Restaurar una copia.\n\nLa copia incluye:\n- configuración SIGAT\n- dependencias\n- tipos de activo\n- marcas\n- personas\n- activos\n- movimientos\n- solicitudes/tickets\n- mantenimientos\n- soportes técnicos\n- conceptos de baja\n\nNO incluye:\n- auth.users\n- contraseñas\n- perfiles/roles de autenticación\n- código, funciones ni estructura SQL\n\nLa restauración conserva el usuario ADMIN y la estructura de Supabase.\nDespués de restaurar, la secuencia de tickets se reajusta automáticamente.\n
